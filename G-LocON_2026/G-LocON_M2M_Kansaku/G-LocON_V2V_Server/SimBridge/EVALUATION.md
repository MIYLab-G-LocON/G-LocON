# 正式評価の手順（自分のPCで実行 → 表 → グラフ）

従来G-LocON（自車の周りの円）と本システム（進行先の交差点）を，同じ交通の上で比べる。
スマホもサーバも使わない。SUMO を走らせ，毎秒「その方式なら誰と誰がつながっているか」を計算して集計する。

指標の定義は上位の [README 7.5](../../README.md)，これまでの試行の記録は [EXPERIMENTS.md](../../EXPERIMENTS.md)。

## 1. 準備（初回だけ）

```
cd G-LocON_V2V_Server\SimBridge
pip install -r requirements.txt
```

SUMO 本体（`eclipse-sumo`），表・グラフ用の `matplotlib`・`openpyxl` が入る。

## 2. 何が動くか

| ファイル | 役割 |
|---|---|
| `compare_schemes.py` | 1回分の計算。SUMO を1回走らせ，その走行の上で全方式の接続を計算して `schemes.csv` を出す |
| `eval_run.py` | 決めた条件の組み合わせで `compare_schemes.py` を繰り返し実行する |
| `eval_report.py` | 結果を集計して，表（CSV・Excel・Markdown）とグラフ（PNG）を作る |

```
SUMO（車の位置・速度，1秒ごと）
   │
   ├─ 本システム: 交差点への ETA < τ，または参加円の中 → 参加。通過して δ 離れ，遠ざかったら離脱
   ├─ 従来100m : 約2秒ごとに問い合わせ，半径100m以内の車とつながる
   ├─ 従来150m : 同上（半径150m）
   └─ 従来200m : 同上（半径200m）
        │
        └─ 方式ごとに同じ基準で集計 → schemes.csv（1行 = 1方式）
```

## 3. 手順

### 3.1 まず1回だけ動かして見る（説明用）

`eval_0_demo_gui.bat` をダブルクリック（または下のコマンド）。sumo-gui が開き，車が走る様子が見える。
終わると `out\compare_demo\schemes.csv` ができ，画面に方式ごとの指標が出る。

```
python compare_schemes.py --tag demo --etas 15:100:100 --radii 100,150,200 --gps-noise 5 --gps-corr 10 --gui
```

### 3.2 動作確認（2実行，数分）

`eval_1_quick.bat` をダブルクリック（または下のコマンド）。

```
python eval_run.py --plan quick
python eval_report.py --plan quick
```

`results\eval\quick\report\` に表とグラフができる。ここまで動けば準備は完了。

### 3.3 正式評価

| 計画 | 内容 | 実行数 | バッチ |
|---|---|---|---|
| `main` | 従来G-LocONとの比較。地図2つ × 交通量3段階 × 測位誤差2通り × 乱数5回 | 60 | `eval_2_main.bat` |
| `params` | 本システムの τ・ρ・δ を1つずつ変える（大学周辺・交通量 中・測位誤差5m）× 乱数5回 | 5 | `eval_3_params.bat` |
| `noise` | 測位誤差の大きさ（3m・5m）と変わり方（ゆっくり・ばらばら）× 地図2つ × 乱数3回 | 24 | なし（コマンドで） |

```
python eval_run.py --plan main --list        # 実行する条件の一覧を見る（実行はしない）
python eval_run.py --plan main --jobs 4      # 実行（同時に4つ。PCのコア数の半分くらいが目安）
python eval_report.py --plan main            # 表・グラフ
```

- 時間の目安: 1実行あたり大学周辺で数分，幹線道路の地図・交通量 多で数十分。`main` 全体で数時間。
- 途中で止めてよい（Ctrl+C）。もう一度実行すると，済んだ分は飛ばして続きから始める。
- 一部だけ実行: `python eval_run.py --plan main --only campus_mid`（条件名にこの文字を含むものだけ）。
- やり直す: `--force`，または `results\eval\main\<条件名>.csv` を消す。
- 幹線道路の地図（`scenario_arterial\area.net.xml`）が無ければ，最初に自動で作る。

## 4. 結果の見方

`results\eval\<計画>\` に1実行ごとの csv（1行 = 1方式），`report\` に集計ができる。

| ファイル | 内容 | 使い道 |
|---|---|---|
| `report\summary.xlsx` | 指標ごとのシートに「平均 ± 標準偏差」（行 = 条件，列 = 方式） | Excel で見る・論文の表にする |
| `report\summary.csv` | 条件 × 方式ごとの平均・標準偏差・実行数（数値のまま） | Excel で自分でグラフを作る |
| `report\summary.md` | 同じ表の Markdown | README・報告資料に貼る |
| `report\fig_<指標>.png` | 指標ごとのグラフ（棒 = 平均，縦線 = 標準偏差） | スライド・論文の図 |
| `report\all_runs.csv` | 全実行の値をそのまま並べたもの | 検算・別の集計 |
| `logs\<条件名>.log` | 1実行ごとの出力 | 失敗したときの確認 |

### 指標

| 列名（csv） | 指標 | 単位 | 良い方向 |
|---|---|---|---|
| `ctrl_per_veh_min` | 制御メッセージ数（サーバとのやり取り） | 回/台・分 | 少ない |
| `peers_mean` | 同時につながる相手の数（平均） | 台 | 少ない |
| `met_margin_es` | エッジサーバ交差点で出会った2台が，判断の余裕より前からつながっていた割合 | % | 高い |
| `noshare_pct` | ルートが1か所も交わらない相手との接続の割合 | % | 低い |
| `reconn_A_per_veh_min` | 境目でのつなぎ直し（切れてから10秒以内に，位置関係がほぼ同じままつながり直した） | 回/台・分 | 少ない |
| `short_pct` | 10秒以下で切れた接続の割合 | % | 低い |
| `enc_connected` | すれ違い全体（距離が初めて30m未満になった2台）でつながっていた割合（参考） | % | 狙いの違いとして示す |
| `wasted_pct` | 無駄な接続（ルートが交わらない，または一度も50m以内に近づかなかった）の割合（参考） | % | 低い |

### 条件の名前

| 項目 | 値 | 意味 |
|---|---|---|
| 地図 | `campus` / `arterial` | 大学周辺（1.8×1.15km，生活道路中心）／幹線道路を含む（3.0×2.7km） |
| 交通量 | `low` / `mid` / `high` | 車の発生間隔。大学周辺 3.0 / 1.5 / 0.75秒，幹線道路 1.5 / 0.9 / 0.6秒 |
| 測位誤差 | `gps0` / `gps5slow` / `gps5rand` | なし／5m・10秒ほどかけて変わる／5m・毎秒ばらばら |
| 乱数 | `s1`〜`s5` | SUMO の乱数と，車の出発地・目的地の乱数（同時に変える） |
| 方式 | `eta_t15_j100_d100` | 本システム τ=15秒，ρ=100m，δ=100m |
| 方式 | `dist_r100` など | 従来G-LocON 半径100m |

## 5. 条件を変えたいとき

`eval_run.py` の先頭にまとめてある。

```python
PROPOSED = "15:100:100"                 # 本システムの既定: τ:ρ:δ
RADII = "100,150,200"                   # 従来G-LocON の半径 [m]
SEEDS = [1, 2, 3, 4, 5]                 # 繰り返し
MAPS = {...}                            # 地図ごとの交通量（車の発生間隔）
NOISE = {...}                           # 測位誤差の大きさと変わり方
PARAM_SETS = [...]                      # params 計画で比べる τ:ρ:δ
```

指標を足す・外すときは `eval_report.py` の `METRICS`（`schemes.csv` の列名を書く）。

## 6. 前提と注意

- 通信の損失・遅延は無いものとして計算している（方式そのものの比較）。実際の通信の性能は実機で別に測る。
- エッジサーバは交通量の多い交差点に置いた「理想的な配置」（大学周辺20か所，幹線道路の地図40か所）。どこに置くべきかは扱わない。
- 測位誤差の大きさ（5m）と変わり方は仮定。実機では測っていない。
- 従来G-LocONは「問い合わせの結果から外れた相手はすぐ切る」として計算している。
- 交通量を変えても，エッジサーバの位置は変えない。
